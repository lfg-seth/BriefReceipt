# Sources and demonstration data

Implementation checked 2026-11-05. Default mode is a populated demonstration. Every fixture is synthetic and dated **2026-11-05**, including the invented headlines, market numbers, event listings, and project evidence. Changing the clock does not make these observations current. Each block retains its own provenance. Missing data in this preview falls back to labeled fixtures; future production collection must still show **Unavailable** under decision 05.

## Weather

The local server requests [Open-Meteo's public forecast endpoint](https://open-meteo.com/en/docs) without credentials. It asks for current model-derived temperature, apparent temperature, humidity, wind, weather code, day/night, and four daily forecasts. Internal values are Fahrenheit/mph; the UI may convert temperatures. Current model time and retrieval time are distinct. Forecast dates use America/Los_Angeles.

Live location support initially covers ZIP **89147** using the explicitly approximate Spring Valley area coordinate **36.11, −115.28**. This is a ZIP-area demonstration coordinate, not a geocoded home address or a resolved ZIP boundary centroid. Other saved ZIPs return the clearly labeled 89147 sample fixture; a ZIP lookup adapter is future work.

This first studio supports clear, rain, cloudy, storm and clear-night conditions. A snow code in the current or four-day forecast returns an explained sample fallback rather than mislabeling snow as rain. A dedicated snow treatment remains future work.

Open-Meteo's [terms](https://open-meteo.com/en/terms) allow the free endpoint for personal noncommercial use, currently under 10,000 calls/day, 5,000/hour and 600/minute. Data attribution uses [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); the displayed source links to Open-Meteo. This local personal application uses no API key. Commercial hosting or redistribution needs a fresh terms review. The service offers no availability guarantee.

## News

The selected live provider is [Guardian Open Platform](https://open-platform.theguardian.com/access/), replacing NASA on `/api/news`. The user selected Guardian and explicitly excluded its content from AI synthesis. The server requests metadata and publisher excerpts from `https://content.guardianapis.com/search`, verifying a developer key before saving `GUARDIAN_API_KEY` in the Git-ignored `.env`. `trailText` supplies the excerpt; `standfirst` is a fallback when that field is absent or empty. HTML markup is removed and entities decoded into plain text. Missing excerpts remain absent. No full article bodies or imagery are collected. Original headlines and links appear with the publisher excerpt and date/time; bylines and categories are retained as data but omitted from the receipt. The user requested small text attribution, replacing the raster logo, with one deduplicated copyright line at the bottom of the receipt. The line appears only when a Guardian item is included.

Four fixed searches cover general (`world|us-news|politics`), business/technology/science, Tesla/SpaceX keywords, and Nevada/Las Vegas/Clark County/Spring Valley keywords. The local-area editor does not alter these queries yet. Each search requests fifty newest candidates; this is partial coverage, not an exhaustive newsroom or local reporting feed. Date-only upstream filters bound discovery, followed by exact preceding-24-hour filtering of original publication timestamps. Non-articles, invalid/future dates, unsafe article URLs and duplicates are rejected. Specialized company/local results win category assignment over broad sections. The receipt filters selected categories and keeps at most five items total. Empty successful searches stay empty. Missing keys and any failed category return Unavailable with no sample or stale substitution.

Successful collections share a twenty-minute memory cache; timestamps preserve original retrieval. Cache hits remove stories that have since aged out of the 24-hour window. An expiry timer clears idle server cache entries. Four upstream requests are serialized with at least 1.1 seconds between starts, six-second timeouts each, no redirects and a 2 MB streamed-response limit. An in-memory guard stops at 480 calls per UTC day, including connection tests. It resets on restart and is not an account-wide quota tracker. Provider 429 responses are surfaced without automatic retry. Browser collection permits 35 seconds. Keys and credential-bearing upstream errors never enter returned data or logs.

Every enabled, available module except News is assessed independently by AI summary. The entire Headlines block is removed from browser summary inputs, filtered again on the server, and excluded from direct generation and web research. Headline-only briefings make no AI request, and changes to news do not change the summary input. Each eligible module contributes zero or one sentence; validation rejects multiple highlights or sentences from one module. Sentences are separated by a blank line on screen and in print. Quiet modules add no text. Missing or duplicate module assessments are rejected. With live data present, sample sections cannot supply live highlights.

Targeted web research can explain public market moves, exceptional weather and public events using whitelisted public observations. It never receives the News module or personal calendar, task, project or custom-note data. Reporting is used only as context for supplied observations, never as standalone news highlights. Only cited research context is passed to the final writer; validated links appear beside the corresponding sentence and persist with the summary. Research notes do not substitute for independently checking every eligible module.

[Standard terms](https://www.theguardian.com/open-platform/terms-and-conditions) restrict printing and AI use (§6(c)(v), §6(g)). The user requests personal accessibility printing; permission remains unverified.

Verification uses synthetic API responses for original metadata, dates, deduplication, caching, request spacing, key persistence/removal, sanitized errors, empty/unavailable results and local-origin protection. Browser checks cover connection, receipt/print rendering, attribution, category selection, disconnect and exclusion from settings exports and AI payloads. No Guardian key is currently saved; actual account compatibility is established on local connection. The old NASA parser remains a tested legacy helper, not a selected live source.

## Adapter behavior and verification

- `GET /api/weather?zip=89147` returns a `WeatherData` object.
- `GET /api/news` returns `{ provenance, items }`.
- Both support `?offline=1`: weather returns labeled samples; Guardian returns unavailable headlines.
- Weather requests have a six-second timeout and ten-minute memory cache. Guardian behavior is described above. Retrieval timestamps remain those of the original fetch, not cache access. Concurrent requests share collection. Cache keys are bounded; arbitrary user URLs are never fetched.
- Actual Node fetches returned **HTTP 200** from Open-Meteo and NASA during implementation. Completed adapters were then verified to return live weather (four local dates, preserved model time) and five live NASA headlines with original publication times and URLs at 2026-11-05 17:30 UTC. The tool sandbox blocked outbound sockets by default; authorized network execution reached both. An ordinary local installation still depends on the user's connectivity and provider availability.
- Fixtures load immediately without either service. No secrets enter client bundles. Guardian requires the optional developer key described above; public-source adapters do not scan folders, start jobs or send printer commands.

## iCloud Calendar

The local server supports optional read-only account discovery and event queries at Apple's `https://caldav.icloud.com/` endpoint, following account-specific Apple CalDAV shards. Authentication uses a dedicated [app-specific password](https://support.apple.com/en-us/102654). Only HTTPS `caldav.icloud.com` and `p<number>-caldav.icloud.com` destinations are allowed, including redirects and discovery URLs. Apple's password is not scoped read-only; this adapter permits only `PROPFIND` and `REPORT`. No event is created, changed, completed or deleted. Protocol behavior follows [CalDAV RFC 4791](https://www.rfc-editor.org/rfc/rfc4791.html); [vdirsyncer's iCloud documentation](https://vdirsyncer.pimutils.org/en/stable/tutorials/icloud.html) documents the practical endpoint/app-password path.

Successful sign-ins persist `ICLOUD_EMAIL` and `ICLOUD_APP_PASSWORD` in the project's Git-ignored `.env`, as authorized by the user. These plaintext values are read only on the server; the browser input clears on submission and passwords never enter browser configuration, settings exports, status responses or logs. `.env` updates use atomic replacement and preserve unrelated settings/comments. After a restart, the first Calendar status/events request restores the account, sharing discovery between concurrent requests. Failed restoration retains the saved values and exposes a sanitized reason with a retry control; rejected new sign-ins do not overwrite credentials. Disconnect invalidates the current connection and removes the two variables from `.env`. Old session-only connections require one new sign-in to populate the file. Account discovery exposes names and opaque IDs, not credential-bearing URLs. Only checked calendars are queried; identically named calendars retain distinct IDs. Editor endpoints remain loopback-only, require a local Host, reject cross-origin/cross-site requests, require JSON for mutations and return no-store responses. Upstream data/errors are bounded and sanitized. This does not implement scheduling.

`node-ical` parses and expands event recurrence, EXDATE exclusions and RECURRENCE-ID overrides. The window includes **today and the next four complete Pacific calendar days**, ending exclusively at midnight on day five. Date arithmetic uses **America/Los_Angeles**, including 23/25-hour daylight-saving days and year rollover; all-day DATE fields retain their calendar day. Floating times use the calendar's supplied timezone, defaulting to Pacific. Ongoing overnight/multi-day occurrences appear once under Today with an Ongoing label; cancelled instances and events ending at today's midnight are excluded. Sort by day, then all-day first within each day, then start time. Today/Tomorrow/weekday headings include the date. The existing item limit applies to the full window, with omitted events disclosed; Calendar settings allow up to 20 items. A broader upstream time filter accounts for floating DATE values; exact date filtering happens locally. Calendar data is not cached, refreshing on selection, explicit refresh, connection changes or the Pacific date changing. Each discovery/collection has a shared 30-second deadline and each upstream response an 8 MB limit. Failed/partial collection returns **Unavailable** without fabricated appointments. A successful empty selection prompts the user to choose calendars, and a successful empty window says no appointments.

Local API: `GET /api/icloud/status`; `POST /api/icloud/connect` with `{email,password}`; `POST /api/icloud/retry` and `/api/icloud/disconnect` with `{}`; `POST /api/icloud/events` with `{calendarIds}` (at most 30 discovered IDs). Status includes whether credentials are saved and any sanitized restore error, never credential values. Tests use synthetic accounts and ICS/DAV responses, verify .env preservation/removal, successful restoration across fresh server instances and retry behavior, and never collect account credentials. Browser tests verify connection, selection, reload, failure, disconnect and exclusion from settings/export. The user's actual saved connection is validated only after local sign-in. Reminders uses a separate optional Shortcut snapshot source.

The UI represents the iCalendar `DESCRIPTION` field as notes beneath the title, with a clipboard icon matching Apple Calendar's Notes terminology. Notes preserve decoded text, including line breaks, punctuation and whitespace. Recurrence-specific notes take precedence over the series notes. Empty notes stay absent. Up to **90 Unicode code points** display verbatim. Optional OpenAI summaries condense longer notes for included live events, with italic styling and no visible AI label or full-notes expansion control. Missing credentials, quota, exhausted monthly allowance, network errors, refusals and invalid/incomplete output retain full notes without truncation and show an explanation. The icon's accessible label is Notes, Full notes or AI summary. Sample calendars and disabled Calendar blocks skip calendar-note compression; the separate AI summary may assess all-sample briefing content when enabled. [Apple-pattern research, prompt and provider behavior](research/calendar-description-summaries.md), [OpenAI setup, data scope and cost guard](../README.md#connect-openai-for-briefing-highlights-and-calendar-notes).

Event rows omit the calendar name and order details as notes, invitees, location, then travel. Calendar names remain available in source settings for selection. Invitee names come from `ATTENDEE`'s `CN`, falling back to the calendar address with a `mailto:` prefix removed. Names deduplicate case-insensitively after normalizing whitespace; conflicting response statuses remain visible as separate icons beside that one name. A profile icon precedes each name. Accepted/declined use check/cross icons; tentative, awaiting response and delegated use clock, question and arrow icons. Missing status has no response icon. All icons carry accessible labels. Invitations never imply attendance. Recurrence-specific invitee lists and locations override their series values; omitted fields inherit from the series. Location and the complete original invitee list (including addresses and supplied status) accompany long notes in the optional OpenAI summary input. These fields are context for understanding the notes; they do not independently trigger AI generation. [iCalendar field definitions](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.1), [Apple's event fields](https://support.apple.com/guide/calendar/add-modify-or-delete-events-icalwr13-events/mac).

US addresses beside the map pin omit country. Addresses matching the configured city **and** state show only street/suite; others retain street plus city, two-letter state and ZIP. Multiline/comma address formats are supported, with full US state names normalized; unrecognized venue text stays intact without guessed geography. Source addresses remain unmodified for future routing and summary context. Sources and Calendar settings expose local city/state (initially Las Vegas, NV for ZIP 89147), home/work origin addresses and sample travel minutes. Update city/state after changing ZIP until automatic lookup is connected.

Recognized destination addresses get two travel rows with home/briefcase icons, configurable placeholder minutes (20/30 initially), and sample leave times calculated from the event start in Pacific time. The receipt omits the Sample travel heading at the user's request; placeholder status remains explained in settings. Missing/all-day starts show a dash, and prior-day departures retain their date. No route, traffic or arrival-buffer calculation is connected, and no saved origins are sent anywhere. Origins persist in this browser and settings exports. ## Apple Reminders Shortcut snapshots

The implemented bridge combines Apple's [Find/Filter actions](https://support.apple.com/en-om/guide/shortcuts/apd3c845e881/ios), [request-body support](https://support.apple.com/en-lamr/guide/shortcuts/apd58d46713f/ios), and optional [personal automations](https://support.apple.com/guide/shortcuts/enable-or-disable-a-personal-automation-apd602971e63/ios). A phone-side Shortcut reads completed and incomplete reminders from explicitly chosen lists and exports title, list name, due day and completion status. Existing Shortcuts remove their incomplete-only filter and add `completed` as Text `true`/`false`, selected by an If on Repeat Item's Is Completed property. It does not use the Calendar password, unofficial iCloud web endpoints or task writes. Pacific phone dates do not preserve due times. Device permissions and locked-phone automation remain user-device validation steps.

`POST /upload` on a separate loopback listener (default **5180**) receives `Authorization: Bearer <token>` and JSON `{version:1,capturedAt:<ISO timestamp>,reminders:[{title,list,due,completed?}]}`. `due` accepts a valid `YYYY-MM-DD`, ISO timestamp with offset, `null` or empty string. `completed` accepts Booleans or the exact text `true`/`false`, normalized to a Boolean; missing fields default false for older Shortcuts. Other values are rejected so text `false` cannot accidentally become truthy. Payloads contain at most 2000 items and 1 MB of JSON; title/list lengths are bounded and unknown fields discarded. Empty arrays clear the snapshot. Invalid, unauthorized and older captures do not overwrite valid data; captures more than two minutes in the future are rejected. Phone uploads cannot read tasks, local controls, the editor, Calendar accounts or settings. No task titles are echoed in upload responses.

Desktop routes `/api/reminders/{status,guide,pair,address,revoke,tasks}` stay on **5173** behind the local host/origin/JSON guard. The latest snapshot, address and token hash persist atomically in ignored `.local/reminders/state.json`. Raw tokens are cryptographically random (32 bytes), returned only during pairing, compared through constant-time SHA-256 hashes, and never saved to disk or browser storage. Replacement/revocation invalidates the old token; disconnect removes the snapshot. The local JSON file is not encrypted. Pairing QR codes are generated locally; the secret is in a URL fragment, stripped by the guide before navigation. Setup pages load no external assets, suppress referrers, prohibit framing and use no-store responses.

Private [Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve) forwards HTTPS **8443** to the upload listener; no Funnel, public service, firewall change or editor exposure was configured. The actual address stays in local state. MagicDNS is enabled on the tailnet, but this computer's Use Tailscale DNS setting is disabled and was left unchanged. The desktop guide opens locally with the upload address supplied separately; the iPhone must connect Tailscale and enable its DNS setting. Direct TLS verification using the Tailscale IP with the correct hostname returned health **200** and editor/account API paths **404**. This establishes host-side serving, not iPhone reachability.

The desktop polls snapshots every 15 seconds in Shortcut mode and settings metadata every ten seconds. Only checked list names are included (names identify lists in this trial). The window includes overdue incomplete reminders plus completed and incomplete items due today through the following **four Pacific calendar days**, fully including day four. Completed overdue items, undated reminders and items beyond day four are omitted. Calendar arithmetic handles daylight-saving and year changes. Results sort by due date, then incomplete before completed within each day. Checked-off rows carry a checkmark, accessible completion text and a struck-through title; due labels remain Today, Tomorrow or weekday names. The receipt retains its configured item limit and discloses omitted rows. Capture and receipt timestamps remain distinct. Missing/stale snapshots (over **two hours**) show **Unavailable**, never sample substitutions. Settings exports contain chosen list names, not task content or tokens. The desktop must be awake with the app running; VM migration and printing schedules remain future work.

Tests cover schema/date limits, empty data, Pacific date filtering, list/completion scope, preserved valid data on failed/older uploads, restart persistence, rotation/revocation, receiver isolation and sanitized errors. Edge tests mock uploads to verify QR rendering, list selection, timestamps, stale labels, token exclusion and mobile guide layout/fragment handling. No personal Reminders data was collected during implementation.

## Markets and other sources

Calendar and tasks default to samples and can optionally connect to iCloud/Shortcut data as described above. Local events and project updates are sample-backed. Markets also default to samples, with an optional live Alpaca connection. Sample markets include only tracked stock rows with fictional prices; Dow and S&P 500 rows have been removed at the user's request. Each row carries a synthetic session, as-of timestamp and freshness label. These are not current factual prices.

**Alpaca (implemented 2026-11-05):** connect Paper Trading API key ID and secret in Markets or Sources → Markets. Access is verified with GET-only paper-calendar and historical IEX stock-bar requests before saving both keys to the Git-ignored `.env`. Credentials are server-only after submission; status, exports and browser storage exclude them. Replacement failures preserve existing keys; disconnect removes only Alpaca credentials. Same-origin loopback checks protect the routes. No orders, subscriptions or paid feeds are requested.

The integration explicitly selects `feed=iex`, not consolidated SIP. Alpaca's [paper-account documentation](https://docs.alpaca.markets/us/docs/paper-trading) limits paper-only entitlement to IEX; the [general market-data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) also describes delayed historical SIP access, which this implementation does not assume. IEX prices and volume represent one exchange. [Historical bars](https://docs.alpaca.markets/us/reference/stockbars) provide split-adjusted OHLCV data, with bounded pagination and response sizes. Upstream requests time out after eight seconds each, with a shared 25-second collection deadline and a 30-second frontend deadline.

The exchange calendar supplies actual regular-session opens/closes, including holidays, early closes and DST. Before opening and when closed, select the latest completed regular-session close, with session-end as-of time. During trading, select the latest regular-session five-minute bar, using its start timestamp conservatively for freshness; missing bars or bars more than 15 minutes old show Unavailable. Daily changes compare against the preceding regular-session IEX close. **1D** plots regular-session five-minute prices; **1W** plots thirty-minute samples across five trading sessions. The weekly percentage compares against the close preceding that window. Fewer than two chart points shows Unavailable. Chart arrays are excluded from AI requests; quote values, session, coverage and unavailable reasons remain eligible evidence.

Dow and S&P index rows are omitted from collection, the receipt and AI inputs at the user's request. Unsupported stock symbols stay Unavailable, without guessed company identities or ETF substitutions. Enabled live markets poll every minute; the one-minute server cache preserves retrieval/as-of timestamps and expires at session boundaries and freshness deadlines. Failures never substitute samples or older-session prices. A real-account collection on November 5, 2026 returned TSLA's completed regular-session price, 78 daily-chart points and 65 weekly-chart points; synthetic API and browser tests also cover the workflow. Credentials were neither displayed nor included in the verification output.

`marketRequestPolicy` preserves the original sample generation-time cutoff: before 06:30 Pacific requests previous completed close; at/after 06:30 requests current/opening data. The live Alpaca collector now uses exchange-calendar session boundaries and the unavailable-current-data behavior described above. Sample values do not change their claimed session when the wall clock changes.

Sample calendar/list names and folder paths are configuration only; connected iCloud calendars use discovered IDs and actual event data. Project sample evidence references fake commits, PRs and dated notes, with supported example next steps/blockers; no repository was read to generate it. Local area settings describe intended coverage, not a connected event collector.

Atmospheric backgrounds and motion are original CSS; no third-party photos or emoji are used.

Receipt presentation update (2026-11-05): following the user's request for a fresh visual design, replace the market table with individual stock sections. Prominent ticker/price headings lead into DAY and WEEK performance rows, each showing a bold percentage with an up/down marker and the dollar gain/loss. Full-width monochrome sparklines have a marked endpoint, with no numeric axes or repeated disclosures. Missing changes show Unavailable; fewer than two valid history points omits that chart. Metadata remains in adapter responses, source settings and AI evidence. Unsupported stocks retain a compact Unavailable value. Browser checks cover gains/losses, normal and 48 mm printable widths, and print visibility.

Market status badge (2026-11-05): the live Markets heading replaces Live with Open, Pre-market, After-hours or Closed, determined in New York time from the current calendar day and its regular/extended session boundaries. Weekends and calendar holidays show Closed. Provider session_open/session_close fields (HHMM) take precedence; absent fields use standard 04:00/20:00 extended bounds on normal days, while an early close without an extended-close field conservatively stops at the known regular close. This describes the regular/pre/post-market schedule, not an overnight trading feed. See [Alpaca calendar](https://docs.alpaca.markets/us/reference/legacycalendar) and [extended hours](https://alpaca.markets/support/extended-hours-trading). Cache expiration respects all session transitions. Known calendar status survives a quote failure, with Unavailable shown for prices; failed calendar access shows Unknown. Samples retain Sample. Quote/chart selection remains based on regular-session data.
